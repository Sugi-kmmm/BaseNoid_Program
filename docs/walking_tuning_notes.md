# 線形倒立振子歩行 調整メモ（2026-10-09〜10）

別の PC で作業を続けるための引き継ぎメモ。ブランチは BaseNoid_Program / BaseNoid_Library ともに `feature/lipm-walking`。

## 1. 歩行アルゴリズムの修正（BaseNoid_Library）

`walking_algorithm.cpp`（梶田式：歩行素片＋着地位置修正）

- Step 8 の修正着地位置の式：`T_c * v` を `T_c * S * v` に修正
- Step 7 の目標重心：前の着地位置ではなく、次の公称着地位置 p^(n) ＋ 歩行素片にした
- Step 5：公称着地位置 `Last_Nominal_Pos_Foot` と修正着地位置 `Last_Pos_Foot` を分けた（以前は修正位置に歩幅を積み上げていて、ずれが蓄積していた）
- Step 6：歩行素片の速度に回転行列を2回かけていたのを修正
- `Initial_CoG_Position()`：静止状態から歩き出すときの重心位置を解析的に求める。これで1歩目が公称位置に着地する

`basenoid.cpp`（Walk）

- `micros()` を基準に実時間で軌道を作る（`Run_Realtime`）。以前は dt=5ms で計算しているのに、待ち時間が 100ms になっていた
- 脚のサーボには `SyncWritePosEx`（応答待ちなし、ACC=0）で指令する（`stream_leg_servo_angle`）
- 遊脚軌道：水平方向はコサイン補間、高さは正弦波
- `Walk_Stop()`：歩幅0で3歩進んで止まり、そのあと3次補間で重心を両足の中点に戻す
- 先行指令：`Servo_Delay` だけ先の目標軌道を指令する。各支持期の最後の `Servo_Delay` 秒は、次の支持期の軌道を送る。そのため、着地位置の計画を1歩の始めに行うようにした
- main.cpp：歩行は `loop()` から毎回呼ぶ。左スティックの上下（`-axisY`）で前進・後退
- 旋回（2026-10-10 追加）：左スティックの左右（`-axisX`）で左旋回・右旋回。前後と同時に入れると曲がりながら歩く
  - 歩幅の向き θ（ワールド座標の絶対角）を `Where_to_Put_Next_Foot` の `Stryde_theta` に渡す（梶田式の s_θ）
  - 旋回する側の足（左旋回なら左足）だけを `Max_Turn_Angle` 回し、反対の足は次の1歩でそろえる。つま先が内側で交差しない。足踏みで旋回すると、支持脚のまわりに回る
  - 遊脚の向きは水平位置と同じコサイン補間。腰の向きは両足の向きの中間
  - 1歩目と2歩目は旋回しない（`Initial_CoG_Position` の前提）。止まるときの3歩は旋回なしで、両足の向きがそろう
  - 再び歩き出すときは、右足の向きを基準に1歩目の歩幅を求める（旋回後に止まっても続けて歩ける）
  - 逆運動学（`kinematics.cpp`）：股関節・足首のオフセットを、ワールド座標ではなく腰・足の座標系で加えるように修正（向きが0のときは以前と同じ結果）。`Pelvis_Offset_x` も腰の座標系で加える

## 4. わかっている問題と、次にやること

- **バックラッシ**：サーボのガタは 3〜4ステップ程度。荷重が抜けると、高いゲインで発散する。持ち上げたときの暴れ方は、歩行以外を P8 にし、不感帯を 4 にして改善した
- **歩行中に遊脚が空中で振動していた**ので、遊脚が空中にある間だけ P32 にする切り替えを実装した。**まだ実機で確認していない**
  - まだ振動するなら `swing_P_gain` を 16 に下げる。足が上がりきらないなら 48 に上げる。着地の瞬間に振動するなら `Swing_Gain_Ratio` を下げる
- **ブラウンアウト**：電源投入時や、ゲインが高いときにリセットすることがある（ログに `Brown...` と出る）。電源と配線の確認が必要
- **旋回はまだ実機で確認していない**。最初は持ち上げた状態で、股関節ヨーが正しい向きに回るか確認する（右足は `mirrorLegJointAngles` でヨーの符号を反転していない）。足先が逆に開くなら符号を確認する
- 必要になったら：`z_m` を上げて膝の負担を減らす、関節ごとに先行時間を変える、バックラッシ補償を入れる

## 5. 測定のしかた

- ○ で歩行準備の姿勢にしてから × を押すと、ゲインスイープが走る（約25秒）。結果はシリアル（115200bps）に CSV で出力される
- シリアルの記録は DTR と RTS を False にしてから開く。そうしないと ESP32 がリセットする
- 起動時に、書き込み前と書き込み後のゲインと不感帯を表示する
- ビルドで `xtensa-esp32-elf-g++: error: CreateProcess: No such file or directory` が出る PC がある。コンパイルのコマンドラインが Windows の上限（約32k文字）を超えるため。標準の `framework-arduinoespressif32` がすでに入っている PC では、Bluepad32 版が `~/.platformio/packages/framework-arduinoespressif32@src-（長いハッシュ）` という名前で入り、インクルードパスが長くなる。このフォルダを `framework-arduinoespressif32@bp32` のような短い名前に変えると直る（PlatformIO は中の `.piopm` でパッケージを見分けるので、再ダウンロードは起きない）

## 6. PC からの PID ゲイン調整（configuration mode）

起動時の3秒の間に `s` を送る（またはトルク OFF のときに START ボタン）と configuration mode に入る。`5` でゲイン調整モードになる。

| コマンド | 内容 |
|---|---|
| `p` | 設定値を表示 |
| `r` | サーボに書き込まれている値を読み出して表示 |
| `w <対象> <P> [D] [I]` | 歩行中のゲイン（`SERVO_ARRAY`） |
| `n <P> [D] [I]` | 歩行以外のゲイン（全サーボ共通） |
| `s <P>` | 遊脚が空中にある間の P（`swing_P_gain`） |
| `z <対象> <step>` | 不感帯（CW/CCW 共通） |
| `save` | フラッシュに保存（次回起動時に読み込む） |
| `default` | ソースコードの値に戻す（保存はしない） |
| `erase` | フラッシュに保存した値を消す |
| `h` / `q` | ヘルプ / 終了（終了時に歩行以外のゲインと不感帯をサーボに書き込む） |

- `<対象>`：サーボ ID（例 `31`）、`all`、`upper`、`leg`、`hip`、`knee`、`ankle`
- 値は 0〜254（255 は「書き込まない」に予約）。`-` はその値を変えない。例：`w leg 64 - -`、`w knee 96`、`s 16`
- 変更は RAM 上の設定値に反映され、歩行開始時（`apply_servo_gain(true)`）と歩行終了時に使われる。`save` しないと電源を切ると消える
- サーボのロックフラグは操作しない（サーボの EEPROM は書き換えない）。保存先は ESP32 のフラッシュ（NVS、名前空間 `basenoid`）
